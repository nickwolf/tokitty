## Slice 1: tray core

Files: new `tokitty/tray_icon.py`, `tokitty/tray.py` (the move only), `tokitty/qt/menu.py`, new `tokitty/qt/tray.py`, new `tests/test_tray_icon.py`, new `tests/qt/test_qt_tray.py`, `tests/test_toolkit_isolation.py`.

1. `tray_icon.py`, no toolkit imports: `TRAY_ICON_SCALE = 2` (moved, with its comment) and `tray_raster(colorway, pattern) -> (width, height, rgba_bytes)`, which is `raster_rgba(get_frames("content")[0], resolve_palette(colorway, pattern), TRAY_ICON_SCALE)`. `tray._default_image_factory` calls it and keeps the PIL padding; `tray.py` imports `TRAY_ICON_SCALE` from it so `tray.TRAY_ICON_SCALE` still resolves.
2. `qt/menu.py`: `render_menu` returns a `sync()` callable. A `dynamic_label` item is always created as an action wired to its (wrapped) action, with text `getter() or ""` and visibility `bool(getter())`, instead of being skipped. `sync()` walks every rendered item, submenus included, and re-reads: text and visibility for `dynamic_label`, `setChecked` for `checkbox` and `radio_selected`. Keep the existing behaviour for every other kind. The right-click menu ignores the return value. Update the module docstring.
3. `qt/tray.py`: `QtTray(menu_provider, state_dir, colorway="orange", pattern="tabby", *, on_action_done=None, icon_factory=None, tray_available=None, platform=sys.platform)`, per spec decisions 2, 3 and 5.
   - Defaults: `icon_factory` is `QSystemTrayIcon` (called with no arguments), `tray_available` is `QSystemTrayIcon.isSystemTrayAvailable`.
   - `__init__` builds the `QIcon` (a square transparent `QImage` of side `max(w, h)`, the `tray_raster` sprite drawn centred, as `qt/kit.py:114-120` turns a raster into a `QImage`) inside a try; `available = tray_available()` and the icon built. Any exception gives False and no icon image.
   - `start()`: no-op unless available and not started. Builds the icon object, `setIcon`, `setToolTip("Tokitty")`, a parentless `QMenu` held on `self`, `self._sync = render_menu(menu, menu_provider(), self._wrap)`, `setContextMenu(menu)`, `show()`. Any exception sets `available` False and drops the icon and menu.
   - `_wrap(action)`: None stays None; else a callable that does `QTimer.singleShot(0, run)`, where `run` calls the action and then `on_action_done`.
   - `refresh()`: `self._sync()` when started, in a try that swallows exceptions (Tk's posture).
   - `notify(title, message) -> bool`: False when not started, when `platform == "darwin"` (before touching the icon), or when `supportsMessages()` is false; else `showMessage(title, message)` and True; an exception gives False.
   - `stop()`: `hide()`, then drop the icon and menu (`deleteLater` on both). Safe when not started.
   - `set_enabled(enabled)`: `update_settings(state_dir, tray_enabled=enabled)`, then `start()` or `stop()`.
   - Module docstring: the GUI-thread model, why the menu is updated in place (spec decision 3), why macOS has no notifications yet (decision 5).
4. Tests:
   - `tests/test_tray_icon.py`, unmarked: `tray_raster` returns the content frame at scale 2 for a given colorway and pattern (compare with calling `raster_rgba` directly); `tray._default_image_factory` gives a square RGBA image of side `max(w, h)` holding those bytes centred (needs Pillow, already a dependency); `tray.TRAY_ICON_SCALE == 2`.
   - `tests/qt/test_qt_tray.py`: the spec's `QtTray`, Menu and `notify` bullets. The fake icon records calls and offers `supportsMessages`, `isVisible`, `contextMenu`. "No action created or deleted" is asserted by collecting the menu's actions (recursively) before and after `refresh`, by identity, including while `menu.isVisible()` is forced true through the fake. The deferral is asserted by triggering an action and checking the callback has not run until `qapp.processEvents()`. One `announcer` test: a fake release, a `QtTray` whose fake supports messages, and `update-state.json` holding the tag only after `notify` returned True; repeat with the darwin platform and assert the tag is absent.
   - Right-click menu: the existing `tests/qt` menu tests (`test_app.py`, `test_input.py`) run unchanged, with one allowed edit: an assertion that lists `menu.actions()` where a `dynamic_label` getter returns no text (`tests/qt/test_input.py` near line 49) compares the visible actions instead, since Qt keeps hidden actions in `actions()`; what the user sees is unchanged. Add one test that a menu rendered with an update label getter returning None shows no visible update action, and after the getter returns text, `sync()` makes it visible with that text.
   - Isolation: `tokitty.tray_icon` joins `_MODULES`; `tokitty.qt.tray` joins `_QT_MODULES`; the Qt isolation test blocks `pystray`, `AppKit`, `Foundation` and `objc` as well as the tkinter names, and its leak check covers them. Run that test against every Qt module, not only the new one.
