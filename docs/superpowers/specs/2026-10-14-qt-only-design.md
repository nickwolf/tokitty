# Make the Qt widget the default and remove Tk (design)

Issue: [#142](https://github.com/nickwolf/tokitty/issues/142), milestone v0.7.0 "Qt widget". The issue text: flip the default to Qt and delete the Tk side (`ui.py`, the colour-key half of `transparency.py`, the system-DPI mode in `dpi.py`, the `gui`-marked Tk tests and their xvfb CI job, the Tk checks in `frozen.py`, and the `TOKITTY_QT` flag). Its three comments add: drop `pystray`, `pyobjc` and `tokitty/tray.py` (from #114, with two Codex findings to revisit); replace Pillow, set `LSUIElement` and give About a new home, and decide what the updater and README do for a Linux user without the xcb packages (from #115, decisions 4 and 7, with #117 item 13); recheck #117 item 3, full screen on macOS, once `LSUIElement` is set (from the #115 Mac checks).

Inputs: the #111 spec (`2026-10-11-qt-main-widget-design.md`), the #114 spec (`2026-10-13-qt-tray-design.md`, decision 1), the #115 spec (`2026-10-13-qt-package-design.md`, decisions 2 to 9 and its Mac results), and the #115 Mac checklist (`docs/superpowers/plans/2026-10-13-qt-package-macos-check.md`). Written against main at 9644fc0 (#115 merged as PR #153).

Status: open questions decided by Nick, 2026-10-14, all as proposed. A Codex review (gpt-6-sol, high) the same day found seven issues; six are folded in and listed with the seventh in the review section at the end.

## Goal

The release bundle carries one GUI toolkit, Qt. Nothing in the frozen bundle imports tkinter, `_tkinter`, pystray, pyobjc (`objc`, `AppKit`, `Foundation`), python-xlib or Pillow, and CI fails a build that carries any of them. Every shipped updater (v0.6.x, which runs Tk, and the #115 `tk,qt` build in either mode) installs the Qt-only build exactly as it installs any other release, proven in CI. On macOS the app is an agent app (`LSUIElement`): no Dock icon, no app menu, About in the menu-bar and right-click menus. The archive sizes are recorded against v0.6.0 and against the #115 build.

## Scope and non-goals

In scope: the launcher, deleting the Tk modules and their tests, the Stream Dock key renderer, the self-check report, the build's dependencies, excludes and licence files, the verifiers, both workflows, `Info.plist`, the About item, the two #114 Codex findings, the README, and the manual checks on Windows and the Mac.

Not in scope: #128 (pixel-exact Qt image tests), #117 (the release gate, which tests the build this produces), the art and animation work in v0.8.0, code signing, and the v0.9.0 notices follow-up (#152) beyond removing the notices for packages that leave.

## Facts this design rests on

Measured or read on 2026-10-14, before any change.

1. **What the frozen Linux build needs from the system.** The Linux artifact of #115's last CI run (38512074951, `tokitty-dryrun-38c6dca-linux-x86_64.tar.gz`) already carries `libxcb-cursor.so.0`, `libxcb-shape.so.0`, `libxcb-icccm.so.4`, `libxcb-keysyms.so.1`, `libxcb-xkb.so.1`, `libxkbcommon-x11.so.0` and the rest of the xcb family in `_internal/`, because the build runner has them installed and PyInstaller collects them. It does not carry `libEGL.so.1`, which PyInstaller leaves to the system as a graphics driver library. Run in a clean `ubuntu:22.04` container with only `xvfb` and `xauth` installed, `TOKITTY_SELF_CHECK_TK=1 TOKITTY_QT=1 xvfb-run -a ./tokitty --self-check` printed a report (exit 1) whose `qt` and `qt_root` entries failed with `ImportError: libEGL.so.1: cannot open shared object file`; with `libegl1` added, `qt_root` passed with `xcb`. In both runs the only other failure was `tls`, because the bare image has no `ca-certificates`. So the hard requirement from the frozen bundle is `libegl1`, and a missing libEGL gives a report with failed entries, not the `qFatal` abort ("printed no report") #115 met. That abort came from libraries missing on the build runner, which therefore never entered the bundle.
2. **Every shipped updater judges the same way.** `update_install.run_self_check` and `child_env` are byte-identical between v0.6.2 and main (`git diff v0.6.2 HEAD -- tokitty/update_install.py` is empty). The judge runs the new copy's `--self-check` with the updater's own environment plus `TOKITTY_SELF_CHECK_TK=1` and `PYINSTALLER_RESET_ENVIRONMENT=1`, and refuses a report that is not JSON, lacks `tk_root`, has any entry whose `ok` is not true, or reports a `build_id` other than the tag.
3. **The new copy inherits the old copy's environment.** The #115 runtime hook assigns `TOKITTY_BUILD_ID` and `TOKITTY_BUILD_TOOLKITS` into `os.environ` unconditionally at every launch (`freeze/tokitty.spec`, the `rthook_build_id.py` writer), so a running `tk,qt` copy has `TOKITTY_BUILD_TOOLKITS=tk,qt` in its environment and passes it to the self-check and to the handover launch. A Qt-mode `tk,qt` copy also passes `TOKITTY_QT=1`.
4. **PySide6 6.12.0's platform floor.** `PySide6-Essentials` 6.12.0 publishes `cp310-abi3` wheels for `macosx_14_0_universal2`, `manylinux_2_34_x86_64`, `manylinux_2_39_aarch64`, `win_amd64` and `win_arm64`, and requires Python `>=3.10,<3.16`. The Qt-only build therefore needs macOS 14 or later, and glibc 2.34 or later on Linux (the ubuntu-22.04 build runner has 2.35, which v0.6.x already required). The #115 build already loads Qt on these floors in Qt mode; what changes is that Tk mode, which ran further back, goes.
5. **Pillow's role.** At run time Pillow has three users: the Tk tray image (`tokitty/tray.py`), the Stream Dock key renderer (`tokitty/streamdock/render.py`), and the self-check's `pil` entry. At build time `tokitty/app_icon.py` draws the `.ico` and `.icns` with it (`freeze/tokitty.spec`), and `scripts/render_media.py` uses it for the README GIF. The renderer draws text with `ImageFont.load_default(size)`, which since Pillow 10.1 is Aileron Regular (Dot Colon, CC0), embedded in Pillow.
6. **Where pyobjc comes from.** Nothing in `pyproject.toml` or the spec names pyobjc. It arrives as pystray's dependency on macOS, and only `ui.register_about_panel` imports `AppKit` (`ui.py:851-858`). The Qt side reaches AppKit through ctypes (`qt/macos.py`), so dropping pystray drops pyobjc.
7. **Full screen on macOS.** `qt/macos.py` already sets `CanJoinAllSpaces | FullScreenAuxiliary` on the widget's window, and the #115 frozen build still did not show it over TextEdit in full screen (#117 item 3). macOS only lets an agent (`LSUIElement`) or accessory app's windows into another app's full-screen Space, so the plist key is the expected fix; the Mac check confirms it.

## Decisions

1. **Qt is the only GUI.** `__main__.main` starts `run_qt` for every GUI launch, including `--after-update` and `--apply-update`. `TOKITTY_QT` is no longer read anywhere (a user or an inherited environment that still sets it changes nothing). `run_gui` and every Tk-only module go: `ui.py`, `settings_ui.py`, `settings_widgets.py`, `settings_accounts.py`, `settings_async.py`, `settings_streamdock.py`, `accounts_ui.py`, `first_run_ui.py`, `update_dialog.py`, `streamdock/presets_ui.py`, `tray.py`, and `dpi.py` if nothing but `run_gui` uses it. Tk pieces inside shared modules go too: the colour-key half of `transparency.py` (keeping the level helpers and whatever Windows helpers Qt calls), `app_icon.photo`, `streamdock/window.tk_view_factory`, and `update_controller`'s `tkinter.messagebox` default, which becomes a required argument or a no-op for the quiet path. A helper that a Qt or toolkit-free module imports from a Tk module moves before the module is deleted (the re-exports in `settings_widgets.py`, `settings_async.py`, `update_dialog.py` and `tray.py` are the known ones). Comments and docstrings that describe a Tk invariant ("the Tk thread", "no tkinter at import") are reworded to what still holds.

2. **The self-check report of the Qt-only build.** Entries: `qt`, `prices`, `hook_writer`, `tls`, and `hook_runner` when frozen; with `TOKITTY_SELF_CHECK_TK=1`, `qt_root`, `tk_root` and `key_font` (the Stream Dock key font registered in the bundle, run after `qt_root` in the same process; shipped judges accept extra ok entries), where `tk_root` carries `qt_root`'s result because every shipped judge requires that key (fact 2; already in `frozen.py` for a build without `tk`). `tkinter`, `pystray` and `pil` go: no judge requires them, and a failed one would refuse the update. `frozen.py` stops reading `TOKITTY_BUILD_TOOLKITS` altogether, and the runtime hook stops writing it, because the variable is inherited from the old copy (fact 3): a Qt-only build that still read it would see `tk,qt`, run the Tk checks against a bundle with no Tk, and be refused by every `tk,qt` updater. The report keeps a constant `"toolkits": ["qt"]` field for the verifiers. A unit test runs `self_check` with `TOKITTY_BUILD_TOOLKITS=tk,qt` and `TOKITTY_QT=1` in the environment, and without them, and requires the same Qt-only key set; CI proves it on the frozen build (decision 8).

3. **The Stream Dock keys are drawn with QPainter, in Aileron.** `render.py` keeps its API and memoisation and draws on a `QImage` (`Format_RGB32`, 64x64) with `QPainter`, encoding PNG through `QBuffer`. The text font is Aileron Regular, shipped as a TTF in `tokitty/streamdock/fonts/` with its CC0 notice and registered once through `QFontDatabase.addApplicationFont`, so the keys look the same on every OS and on a Linux system with no fonts configured, and look like today's keys. The TTF is the one Pillow embeds (fact 5), extracted once by a committed script, or the upstream release file if its licence and glyphs match; the slice decides which and records why. The TTF is listed in `bundle_data.DATA_FILES` and in `pyproject.toml`'s package data, and slice 4 checks that the frozen self-check registers it (decision 2's report gains no entry for it; the check is in `verify_artifact`'s `bundle_contents` and a source test that reads it through `importlib.resources`). Pixel sizes, anchors and the truncation rule (`_fit`) keep their meaning; text is drawn with antialiasing on, so the pixels are not Pillow's. Rendering needs a `QGuiApplication`, which `run_qt` creates before the deck starts, and it runs off the GUI thread: the runtime's `tick()` publishes key specs on the GUI thread, but `DeckServer._plan_body` turns them into images in a `ThreadingHTTPServer` request handler (`streamdock/server.py:186`). Qt allows `QPainter` on a `QImage` in a worker thread, text included. Qt 6 has no `supportsThreadedFontRendering()` to ask (PySide6 6.12 has no such attribute), so `qt`-marked tests draw a titled key on a worker thread and through a real `/plan` request and compare it with the GUI-thread render, on all three systems in the `qt` CI job; if any fails, rendering moves to the GUI thread (the runtime publishes images rather than specs) instead. Otherwise the renderer stays where it is; the font is registered on the GUI thread before the deck server starts (`register_font()`, called by `run_qt`), and the renderer raises rather than drawing with a fallback font if registration did not happen. The `lru_cache` memoisation is thread-safe for this use (a race only renders a key twice). The renderer's tests become `qt`-marked; they keep the size, determinism (equal inputs give equal bytes within one process) and truncation checks, and add a check that the font loaded (an unloaded font falls back silently) and a test that renders through a real `/plan` request on the server's thread. No pixel comparison against Pillow output; #128 covers reference images.

4. **Runtime dependencies.** `pyproject.toml`: `dependencies = ["PySide6-Essentials==6.12.0"]`; the `qt` extra goes (pip warns about an unknown extra and installs the rest, so an old `pip install .[qt]` still works); Pillow moves to the `packaging` extra (build-time icon drawing, fact 5) and to `dev` (the media scripts). `freeze/release-constraints.txt` drops its pystray and python-xlib pins. `bundle_data.qt_version()` reads the PySide6 pin from the `qt` extra today and raises without it, and the macOS `BUNDLE` calls it through `info_plist()`, so it moves to the `dependencies` list, tested against the real `pyproject.toml`. The GUI Analysis in `freeze/tokitty.spec` excludes `tkinter`, `_tkinter`, `PIL`, `pystray`, `objc`, `AppKit`, `Foundation` and `Xlib`, so a stray import fails at run time in CI rather than quietly growing the bundle; the self-check's `qt_root` proves the app starts without them. `freeze/licenses/` drops `pystray-NOTICE.txt`, `python-xlib-NOTICE.txt` and `LGPL-2.1.txt`, leaving `LICENSE`, `LGPL-3.0.txt`, `GPL-3.0.txt` and `Qt-NOTICE.txt`, plus the Aileron notice if decision 3 ships one. `bundle_data.LGPL_SOURCE_PACKAGES` and `VERSIONED_NOTICES` shrink to PySide6 and shiboken6. The macOS copyright line from #115 decision 5 stays.

5. **macOS: an agent app, with About in the menus.** `bundle_data.info_plist` sets `LSUIElement` to true. The app menu goes with it, so `make_app_menu` and its call in `run_qt` go, and "About Tokitty" becomes an item in the shared menu model (`tokitty/menu.py`) that both the menu-bar (tray) menu and the right-click menu render, after Settings. It appears on every platform: on macOS it opens the native panel (`show_about`, unchanged), elsewhere the version box `show_about` already shows. Windows and Linux gain one menu item (open question 1). Command-comma for Settings goes with the app menu, and so does Command-Q. The first-run walkthrough runs before the widget and the tray exist (`qt/app.py:261`), and its close button means Skip, which marks onboarding done, so on macOS it gets a Quit shortcut (`QKeySequence.Quit`) that exits without marking it, leaving the walkthrough to show at the next launch. An agent app is not activated when it opens a window, so Settings, the update dialog, the accounts window, the first-run walkthrough and About must come to the front when opened from a menu; the slice checks how each is shown and activates the app where Qt does not (`QWidget.activateWindow` and `raise_`, or `NSApp activateIgnoringOtherApps:` through `qt/macos.py`). A source run has no `Info.plist` and keeps its Dock icon; the frozen build is what the Mac checks test. The macOS notify gate stays (#115 decision 9); the Mac checklist reruns the notification trial once under `LSUIElement`, and the gate only goes if that trial shows the first toast arriving without the permission prompt eating it. The bundle identifier is unchanged, so the permission a user already gave carries over.

6. **Linux: one package, named in the README and by the refusal.** By fact 1 the frozen bundle needs only `libegl1` beyond what any X11 desktop has. The README's Linux section names `libegl1` alone, and says the other X11 libraries are inside the archive. The build job keeps installing the full xcb list, because that is what puts them in the bundle, and `verify_artifact`'s `bundle_contents` step requires them in `_internal/` on Linux so a runner change cannot silently drop them. A user without libEGL who updates is refused with a report, not an abort: a v0.6.x or `tk,qt` updater says "The new version failed its self-check: qt, qt_root, tk_root." From this build on, `run_self_check` adds the first failed entry's detail to the message (truncated to one line), so a later refusal names `libEGL.so.1`. The v0.7.0 release notes say Linux needs `libegl1`, macOS 14 and Windows 10 1809 or later (fact 4). No preflight in the self-check: with the platform plugins bundled, the remaining dependency fails as a clean `ImportError`, which the report already carries.

7. **The two #114 Codex findings.** The tray setting gets one source of truth in `run_qt`: the value the Settings toggle reads and writes is the value `QtUpdateHost.restore` uses, so a handover that is rolled back restores the tray the user last chose in this session. A tray whose `start()` fails after the probe said it was available is treated as unavailable from then on: `QtTray` records the failure, the Settings row and the menu's tray toggle read it live rather than from launch time, and `restore` does not try to show it again. The slice adds a test for each.

8. **CI.**
   - `ci.yml`: the `smoke` job (xvfb Tk boot, `pytest -m gui`) and the `gui` marker go. PySide6 is now a dependency, so the `test` job installs it; `qt`-marked tests still run in the `qt` job with `QT_QPA_PLATFORM=offscreen`, unchanged apart from tests moving into it (the renderer's).
   - `release.yml`: `TOKITTY_BUILD_TOOLKITS` goes. `verify_artifact` runs once (the Qt pass becomes the only pass; `--expect-toolkits` goes and the step requires `"toolkits": ["qt"]`); `tk_without_qt` goes. `bundle_contents` gains a forbidden list (any file or directory for Tcl/Tk, `_tkinter`, `PIL`/`pillow.libs`, `pystray`, `objc`/pyobjc, `Xlib`) and the Linux xcb list from decision 6. `verify_update`'s new-copy checks become Qt-only: the `after-update-qt.json` check (`exposed_before_ack` true) applies to every pass, and `QT_QPA_PLATFORM` and `WAYLAND_DISPLAY` are always removed. The old copy's mode becomes its own option, `--old-mode tk|qt` (default `tk`), which alone decides whether `TOKITTY_QT=1` is in the old process's environment, since a `tk,qt` launcher picks its toolkit from it (`__main__.py:617`). The v0.6.2 launcher ignores it on `--apply-update` (Codex checked the tag), so the v0.6.2 pass is unaffected either way.
   - Legacy passes, each running `apply_update` and `no_ack_rollback`, so a shipped updater's rollback from a Qt-only child that never acks is proven too (the macOS swap-back and the `current` restore on Windows and Linux): the existing v0.6.2 pass (Tk updater, Qt-only new copy), and a new `tk,qt` pass run twice, with `--old-mode tk` and `--old-mode qt`. The `tk,qt` old copy is built in the same job from the pinned commit 9644fc0 (workflow variable `TKQT_REF`) with `TOKITTY_BUILD_TOOLKITS=tk,qt` and build ID `v0.6.99`, in a separate checkout (open question 2). The inherited `TOKITTY_BUILD_TOOLKITS=tk,qt` is exactly what this pass exercises (fact 3).
   - Linux: a `clean_system` step runs the frozen self-check in a `ubuntu:22.04` container with only `xvfb`, `xauth`, `ca-certificates` and `libegl1`, and requires a passing report; and once more without `libegl1`, requiring a printed report whose failed entries are exactly `qt`, `qt_root` and `tk_root`. This proves the README's one-package claim and that the refusal is clean.
   - The step summary keeps the archive sizes; the spec's Sizes section records them against v0.6.0 and the #115 build.

9. **README.** Install: Linux needs `libegl1`; macOS 14 or later; Windows 10 1809 or later. The tray paragraph's "macOS has no tray icon" becomes the menu-bar cat. The testing section loses the xvfb Tk boot and `python3-tk` notes. Source install: `pip install -e .` now pulls PySide6. The licence paragraph drops pystray and python-xlib. Nothing mentions `TOKITTY_QT`.

## Open questions

All three decided by Nick on 2026-10-14, as proposed.
