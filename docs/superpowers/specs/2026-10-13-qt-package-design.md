# Package and ship the Qt build (design)

Issue: [#115](https://github.com/nickwolf/tokitty/issues/115), milestone v0.7.0 "Qt widget". The issue text: `pyproject.toml` gains `PySide6-Essentials`, `freeze/tokitty.spec` excludes the Qt modules and plugins we don't use, and releases ship the LGPL notices. Record the new asset sizes against v0.6.0. The auto-updater downloads the whole bundle, so a bigger build makes every update bigger. Linux keeps building, but translucency there is best-effort. Its comment, from the spike (#109): plan on replacing Pillow, add the licence files, trim by file name, keep QtDBus.

Inputs: the spike findings (`2026-10-10-pyside6-spike-findings.md`, sections 8 and 9), #113's decisions 7 and 8 (`2026-10-12-qt-updater-design.md`), #114's decisions 1, 5, 8 and 10 (`2026-10-13-qt-tray-design.md`), and the #117 Mac checklist (comment 6126545230, items 3, 13, 14 and 15 wait for this issue). Siblings that stay out: #142 (Qt becomes the default, Tk and its dependencies leave the bundle), #117 (the release gate).

Status: open questions decided by Nick, 2026-10-13, all as proposed. A Codex review (gpt-6-sol, high) the same day found five issues; they are folded in and listed in the review section at the end. Written against `qt-package-115` at 879d39c (main after #113 and #114).

## Goal

Every release archive carries PySide6 next to Tk, trimmed to what Tokitty loads, with the Qt licence notices inside it, and is proven in CI on Windows, macOS and Linux by the self-check in both modes and by the update rehearsal in both modes. A user on v0.6.x who has never heard of Qt updates to it exactly as before. The new sizes are measured and recorded against v0.6.0.

## Scope and non-goals

In scope: the release build's dependencies and toolkit declaration, the trim, the licence files and where they land, the self-check rule for a build that carries both toolkits, the artifact and update verifiers' Qt passes, the release workflow, the README's install and licence text, the macOS checks that need a frozen Qt bundle (notifications, the About panel's contents), and the size record.

Not in scope: anything the Tk path does (it does not change until #142, with two exceptions that come with putting Qt in the same bundle and are stated where they arise: PyInstaller's runtime hook imports QtCore on every launch, decision 2, and the macOS copyright string gains the Qt line, decision 5); removing Tk, pystray, pyobjc or Pillow from the bundle (#142, decision 4); making Qt the default (#142); `LSUIElement` (decision 7); code signing; licence notices for the non-Qt dependencies beyond pystray (decision 5).

## Proposed decisions

1. **The release build installs the `qt` extra and declares `tk,qt`; PySide6 stays an extra in `pyproject.toml`.** `pyproject.toml:13` already has `qt = ["PySide6-Essentials==6.12.0"]` (#111), pinned to the version the spike measured. Moving it into `dependencies` would make every `pip install` of a Tk-mode source checkout pull Qt, which is #142's change, so it stays an extra and the build job's install becomes `pip install -e ".[packaging,streamdock,qt]"` (`release.yml:39`). The build job sets `TOKITTY_BUILD_TOOLKITS: tk,qt` at job level, so the release build, the v0.0.1 fixture and the rehearsal build (`release.yml:73-76, 179-195`) all declare the same thing, and the runtime hook bakes it (`freeze/tokitty.spec:32-39`). The `keychain` job keeps the default `tk`: it installs no Qt and checks only the Keychain. PySide6 is collected without a spec change (the #113 local rehearsal found PyInstaller 6.22.3 collects it from the build venv on its own, through the imports under `tokitty/qt/`), so the spec change is only the trim (decision 3).

2. **In a build that carries Tk, the Qt checks run only for a Qt-mode launch. This amends #113 decision 7.** Every shipped updater runs the new copy's `--self-check` with `TOKITTY_SELF_CHECK_TK=1` (`update_install.child_env`, `:121-135`) and refuses a report that is missing `tk_root`, has any failed entry, or is not JSON (`run_self_check`, `:368-395`). Under decision 7 as written, a `tk,qt` build runs `qt` and `qt_root` on every update, so the user's machine has to be able to start Qt for a Tk-mode update to go through. On Linux it often cannot: Qt's xcb plugin needs `libxcb-cursor0`, `libxcb-icccm4`, `libxcb-keysyms1`, `libxcb-xkb1` and `libxkbcommon-x11-0`, and without them Qt calls `qFatal`, which aborts the whole self-check process before it prints anything (found in the #113 rehearsal: exit 134, "printed no report"). A Linux Tk user missing one package would be refused every update from now on, for a toolkit they never run. So:
   - In a build whose declaration names `tk`, the `qt` and `qt_root` entries are present exactly when `TOKITTY_QT=1` is in the environment. The updater passes its own environment to the self-check (`child_env(os.environ, ...)`, `update_install.py:121-135`), and the handover launches the new copy with it again (`update_controller.py:451`), so the check follows the mode the new copy will actually run in. A Tk-mode update's report has the same keys as today's (plus the `toolkits` field, which no judge reads), and `self_check` itself never imports PySide6 in Tk mode.
   - PyInstaller's PySide6 runtime hook (`PyInstaller/hooks/rthooks/pyi_rth_pyside6.py`, 6.22.3) runs before Tokitty's entry point on every launch of a bundle that collected PySide6, Tk mode and `--self-check` included. It sets `QT_PLUGIN_PATH` and `QML2_IMPORT_PATH` and then imports `PySide6.QtCore` to embed a `qt.conf` (`_pyi_rth_utils/qt.py`, `create_embedded_qt_conf`), inside `try: ... except ImportError: return`. A QtCore library that fails to load raises `ImportError` there and is skipped, so a Tk-mode launch survives a broken QtCore. A crash inside QtCore's own initialisation would not be caught, so CI proves the survival on the frozen bundle rather than trusting the reading (decision 6, `tk_without_qt`), and slice 2 measures what the import costs a Tk-mode start.
   - Qt mode is per launch. Login autostart registers only the executable (`autostart.py:24, 164, 193, 259`), so a user who opted in with `TOKITTY_QT=1` and updated in Qt mode starts in Tk mode at the next login. That is the opt-in as it stands until #142, not a route to an unchecked Qt copy: the copy the updater launches is the one it checked.
   - In a build without `tk` (#142's), nothing changes: `qt` and `qt_root` are always present and `tk_root` carries `qt_root`'s result (`frozen.py:216-220`), because then Qt is the only mode.
   - The reason #113 gave for "present exactly when declared" still holds where it matters. A Qt-mode user still gets a real Qt check before an update is accepted, and CI checks both modes of every build (decision 6), so a broken Qt in the bundle cannot ship. What is given up is a Tk-mode user's update catching a broken Qt that CI missed, which costs that user nothing until they switch modes, and switching modes is opt-in until #142.
   - A Qt-mode Linux user missing the xcb packages is still refused, which is right, since that copy could not start. The refusal says "printed no report", which names nothing. Decision 8 puts the packages in the README rather than adding a preflight to the self-check, because the preflight would have to predict which platform plugin Qt picks.

3. **The trim works on paths inside the PySide6 tree, by component, after Analysis.** The spike's spec (`spike/qt_card.spec` on `spike/pyside6`) dropped any collected file whose destination contained one of a list of fragments ("tls", "generic", "translations" and others) anywhere in the path. In the app that would also match Tokitty's and Python's own files (any path with "tls" in it), so the filter here only looks at entries whose Analysis destination is under the PySide6 tree (`PySide6/...`; on macOS the frameworks are `PySide6/Qt/lib/<Name>.framework/...` at that point), and it matches whole path components or library base names, not substrings. It runs on the Analysis TOCs, before COLLECT and BUNDLE, so the macOS bundle is laid out and signed from the trimmed list; slice 4 inspects the built `.app` (`codesign --verify --deep`) rather than assuming the relocation and signing come out right. The lists and the predicate live in `freeze/bundle_data.py` (`QT_EXCLUDED_MODULES`, `qt_entry_dropped(dest, platform)`) so they can be unit tested; the spec calls them on `gui.binaries` and `gui.datas`.
   - Python modules excluded from the GUI Analysis: every `PySide6.Qt*` binding except QtCore, QtGui and QtWidgets, which are the only three `tokitty/` imports (`grep` over `tokitty/` finds no other). The hook Analysis adds `PySide6` and `shiboken6` to its existing excludes (`tokitty.spec:51`), so the hook executable never carries Qt.
   - Libraries dropped: Network, Pdf, Qml, QmlModels, QmlMeta, QmlWorkerScript, Quick, OpenGL, OpenGLWidgets, Svg, VirtualKeyboard, and the software OpenGL fallback `opengl32sw.dll` and `d3dcompiler_*.dll` on Windows. Plugin directories dropped: `imageformats`, `iconengines`, `generic`, `networkinformation`, `tls`, `qmltooling`, and the `translations` directory. Kept: `platforms` (the window system plugin, without `qoffscreen`, `qminimal` and `qdirect2d`), `styles`, `platformthemes`, `platforminputcontexts` on Linux (IBus and compose input for the Settings text fields, a few hundred kilobytes, dropped by the spike), `xcbglintegrations` on Linux, and QtDBus everywhere, which QtGui links on macOS and the xcb plugin links on Linux (spike section 8).
   - Linux ships the xcb platform only: the `wayland-*` plugin directories and the Wayland platform plugins are dropped. The widget positions itself with `move()` and keeps itself on top, neither of which a Wayland client may do, and Tk runs through XWayland today. With no Wayland plugin and `QT_QPA_PLATFORM` unset, Qt 6.12 tries its default list and takes xcb when `DISPLAY` is set (`qguiapplication.cpp`, platform selection; checked by hand in slice 2 with `WAYLAND_DISPLAY` set). An explicit `QT_QPA_PLATFORM` replaces that list, so a session that exports `QT_QPA_PLATFORM=wayland` would make Qt abort. So a toolkit-free helper, `frozen.qt_platform_env(environ)`, used by `run_qt` before it creates the `QApplication` and by `_check_qt_root`, sets `QT_QPA_PLATFORM=xcb` in a frozen Linux build when the variable names only Wayland platforms and `DISPLAY` is set, and prints one line saying so. A source run is left alone, since a pip-installed PySide6 has the Wayland plugin.
   - The GTK 3 platform theme on Linux pulls GTK into the bundle (spike section 8). Decided in slice 2: it goes. Removing the plugin alone left its libraries behind, because PyInstaller resolves dependencies during Analysis, so the libraries only it links (found with an `ldd` closure over a trimmed build: GTK, GDK, gdk-pixbuf, atk, at-spi, cairo, pango, epoxy, harfbuzz, graphite2, fribidi, thai, datrie, pixman, libjpeg 8) are dropped by exact soname (`bundle_data.GTK_THEME_LIBS`), the one place the trim reaches outside the PySide6 tree. The X11 extension and glib libraries GTK also pulls in stay, since libX11 and Qt can load those with `dlopen`, which `ldd` does not show. Without the theme the colour picker and folder chooser in Settings are Qt's own dialogs rather than GTK's; the windows themselves are styled by the #112 kit either way. The eglfs, linuxfb, vkkhrdisplay and vnc platform plugins and `egldeviceintegrations` go too, with the EglFS libraries, so Linux carries xcb alone.
   - The verifier fails the build if a dropped name reappears or a kept one goes missing (decision 6), so a PyInstaller or PySide6 hook change cannot quietly undo the trim or remove QtDBus.
   This is a denylist, so something new that a later hook collects ships until someone notices the size. An allowlist would fail closed on that but would also break the build on any new library Qt really needs; with the self-check's `qt_root` in CI on every OS, a missing library would be caught too, so either works. The denylist is what the spike measured.

4. **Pillow stays, and the sizes are recorded with it.** The spike's "plan on replacing Pillow" assumed a port that drops Tk at the same time. In this issue Pillow has three users and none of them can go: the Tk tray image (`tokitty/tray.py:28`, Tk path), the Stream Dock key renderer (`tokitty/streamdock/render.py:15`), which Qt mode runs too (`qt/app.py:233-238, 488-555`), and the self-check's `pil` entry (`frozen.py:111-114, 196`), which every report carries. Replacing the Stream Dock renderer with `QPainter` would leave Pillow in the bundle for Tk anyway, so it would save nothing until #142. So #115 keeps Pillow, records the sizes with it, and the `QPainter` renderer and dropping Pillow move to #142, where Tcl/Tk, pystray and pyobjc leave too. A comment on #142 records the move (with Nick's OK). Until then the bundle carries both toolkits, so it grows by about the whole of Qt rather than by Qt minus Tk: by the spike's split, Windows about 22,417,629 + 16,626,144 = 39,043,773 bytes (+74%) before measurement.

5. **The Qt notices ship inside the bundle, with pystray's.** `freeze/licenses/` is committed and holds:
   - `LGPL-3.0.txt` and `GPL-3.0.txt` (the LGPL incorporates the GPL), verbatim from the FSF.
   - `Qt-NOTICE.txt`: the bundle contains Qt 6.12.0 and PySide6 and shiboken6 6.12.0 under LGPL-3.0; links to the exact source releases (`qtbase-everywhere-src-6.12.0` on download.qt.io and the `pyside-setup` 6.12.0 tag); where the Qt libraries are in each archive and that they can be replaced with a compatible build of the same version (the relinking the LGPL asks for, which the one-folder layout allows, spike section 9); and the third-party components inside the shipped Qt modules with their licence texts. That list is generated from the `qt_attribution.json` files of the qtbase 6.12.0 source release for the modules and plugins the trimmed bundle keeps, by a small script committed beside it (`freeze/qt_notices.py`), rather than copied from Qt's web page, which tracks the current release (spike section 9). On Linux it adds ICU, whose libraries the wheel ships.
   - `pystray-NOTICE.txt`: pystray is also LGPL-3.0 and has shipped in every frozen build without a notice. It costs one file now that the LGPL text is in the bundle.
   - `LICENSE`: Tokitty's own MIT licence, which the bundle has not carried either.
   - `python-xlib-NOTICE.txt` and `LGPL-2.1.txt`: pystray pulls in python-xlib on Linux, which is LGPL-2.1-or-later and was missing from the first list.
   - Replaceable code (slice 2): PyInstaller compiles pure-Python packages into its PYZ archive, where nobody can swap them, so pystray, python-xlib, PySide6 and shiboken6 are collected with `module_collection_mode` "py" (`bundle_data.LGPL_SOURCE_PACKAGES`) and ship as plain `.py` files beside their binaries. The notices say where.
   - ICU (slice 2 review): the Linux wheel ships ICU 73.2, so its notice is `icu4c/LICENSE` from unicode-org/icu at `release-73-2`, verbatim, which `qt_notices.py` requires as an argument; it never reads the build host's ICU copyright file.
   They go where a user opening the archive sees them: on Windows and Linux a `licenses/` folder beside the executable (`Tokitty/licenses/`, `tokitty/licenses/`), copied into the COLLECT output by the spec after COLLECT runs, since data files would land in `_internal/`; on macOS `Tokitty.app/Contents/Resources/licenses/` as data files, because the archive may hold nothing but `Tokitty.app` (`update_install.validate_layout`, `:221-231`, which on the other systems checks only the top-level folder, so a folder inside it is fine). The release job's asset count stays at 5 (`release.yml:362-376`).
   - LGPL-3.0 section 4(c): a combined work that displays copyright notices while running must include the library's notice among them and point to the GPL and LGPL copies. The macOS About panel shows `NSHumanReadableCopyright` from `Info.plist` (`bundle_data.py:30-37`), so that string gains a second line: "Includes Qt 6.12.0 and PySide6 6.12.0 under the LGPL-3.0, see Contents/Resources/licenses." The Tk About panel reads the same key (`ui.py:843-867`), so Tk mode shows the line too. That is a change in bundle data, not Tk code, and it is true of the bundle in either mode, since both carry Qt. Windows and Linux show no copyright at run time, so the files are enough there. The README's License section says where the files are and how to replace the Qt libraries; the README is not in the archives, so `Qt-NOTICE.txt` says the same. Notices for the rest of the bundle (Python, Tcl/Tk, Pillow, OpenSSL, certifi) are not part of this issue; v0.9.0's exit criteria include licences, and a follow-up issue there carries them (filed with Nick's OK).

6. **CI proves both modes of every build on all three systems.** In the build job:
   - Linux installs the five xcb packages from decision 2 next to `xvfb` (`release.yml:41-43`).
   - `verify_artifact.py`'s self-check step runs twice: as now, and again with `TOKITTY_QT=1`, where it also requires `qt` and `qt_root` and checks the reported Qt version matches the version in `Qt-NOTICE.txt` (so a PySide6 bump without new notices fails). A new `bundle_contents` step requires the five licence files and checks the trim from decision 3 (dropped names absent, QtDBus and the platform plugin present). A new `tk_without_qt` step copies the app dir, deletes the QtCore library from the copy, and requires the Tk-mode self-check (with `TOKITTY_SELF_CHECK_TK=1`, without `TOKITTY_QT`) to print a passing report: the frozen proof for decision 2 that a v0.6.x Tk user's judge is not exposed to Qt loading.
   - `verify_update.py` runs twice: the existing run, which stays Tk mode, and a Qt pass with a new `--qt` flag, which sets `TOKITTY_QT=1` in every child's scratch environment and removes `QT_QPA_PLATFORM` and `WAYLAND_DISPLAY` from it (the rehearsal must run on a real platform plugin, #113 decision 8), runs only `apply_update` and `no_ack_rollback` (the checksum, layout and cleanup steps do not depend on the toolkit), and in `apply_update` requires `after-update-qt.json` in the state dir with `exposed_before_ack` true (`qt/app.py:30, 591`).
   - Both passes run on a `workflow_dispatch` rehearsal and on a tag push, so the published archive is the one checked.
   - **A shipped updater installs the new build.** The v0.0.1 fixture is a rebuild of the same commit, so it judges with this branch's `run_self_check`, not the one in users' installs. A third pass downloads a pinned published release for the runner's target (`gh release download`, workflow variable `LEGACY_TAG: v0.6.2`, moved on purpose rather than following "latest", so the pass keeps testing the v0.6.x judge) and uses it as the old copy: `verify_update.py` gains `--old-tag` (default `v0.0.1`), which replaces the `OLD_TAG` constant everywhere it is used: the tag check in prepare, the old copy's folder in `Scenario` (`verify_update.py:565, 582`), and the macOS backup and rollback expectations (`:901, 975`). The pass runs `apply_update` only, in Tk mode, since v0.6.2 has no Qt in its bundle. The v0.6.2 source has the hooks the verifier drives (`TOKITTY_UPDATE_API_URL`, `SSL_CERT_FILE`, `--apply-update`; Codex checked the tag). The new side must be newer than the release, so the rehearsal build's tag moves from v0.0.2 to v99.0.0 (`release.yml:156-160, 186-195`); on a tag push the new side is the real tag. This is the direct proof of "nothing in #115 breaks the update for v0.6.x users".
   - The step summary adds the archive size in bytes next to the extracted size.

7. **`LSUIElement` waits for #142.** The main-widget spec said `LSUIElement` comes with #115 (`2026-10-11-qt-main-widget-design.md:116`), and #117 item 13 checks for it. But it is an `Info.plist` key, so it applies to the whole bundle, in both modes: Tk mode would lose its Dock icon and its app menu, which is where the Tk About panel lives (`ui.py:843-867`), and Tk on macOS has no tray (#45), so the right-click menu would be the only way in. That changes the Tk path. It would also hide the Qt About item, which #114 put in the app menu (`make_app_menu`). The runtime alternative, `setActivationPolicy:` to accessory through `tokitty/qt/macos.py` in Qt mode only, would leave Tk alone, but it shows a Dock icon for a moment at every launch and still hides the About item, which would then need a home in the tray menu on macOS. So #115 leaves the plist as it is, the frozen Qt build on macOS has a Dock icon and an app menu as a source run does, and #142, which removes Tk, adds `LSUIElement` together with an About item in the menu-bar menu. #117 item 13 moves to #142 (comment with Nick's OK). Open question 1.

8. **README: install requirements and licences.** The Linux install section lists the five packages Qt mode needs (decision 2) and says translucency there depends on a compositor and is best-effort, as the issue says. Qt mode is still reached with `TOKITTY_QT=1`; the README does not advertise it yet (the #111 to #114 pattern), so the packages are worded as "Qt mode, which becomes the default in v0.7.0, needs". The License section gains the licences paragraph (decision 5).

9. **macOS notifications get one real try in the frozen bundle.** `QtTray.notify` returns False on macOS without calling `showMessage` (`qt/tray.py:128-138`, #114 decision 5), because Qt 6.12's Cocoa tray posts through the deprecated `NSUserNotificationCenter` and may drop the toast without a word. To try it, a debug variable `TOKITTY_DEBUG_NOTIFY=1` makes `run_qt` send one test message through the tray 5 s after it starts, with the macOS gate lifted for that call only, and print `notify: submitted` or the exception to stderr. Nick runs the frozen app from Terminal (`TOKITTY_QT=1 TOKITTY_DEBUG_NOTIFY=1 .../Tokitty.app/Contents/MacOS/Tokitty`) twice. If the toast appears both times, the macOS gate goes and `notify` behaves as on Windows; if it does not appear, or only after a permission prompt that a user would have to find, the gate stays and the finding goes in this spec. The variable stays either way; it costs a few lines and works on every platform.

10. **The frozen About panel is a manual check.** `show_about_panel` (`qt/macos.py:131-153`) reads the name, version and copyright from the bundle's `Info.plist` (`freeze/bundle_data.py:30-37`). From the frozen Qt build, with the app menu present (decision 7), Nick opens Tokitty ▸ About Tokitty and checks it says "Tokitty", the version once, "Copyright © 2026 Nick Wolf. MIT License." and the Qt line from decision 5.

## Review (Codex, 2026-10-13)

gpt-6-sol at high effort, read-only, briefed cold. Each claim was checked against the code or PyInstaller's installed sources before anything here changed.

1. PyInstaller's PySide6 runtime hook imports `PySide6.QtCore` on every launch, so "a Tk-mode self-check never imports PySide6" was wrong for the frozen bundle.
